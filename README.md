# B站稍后再看排序

Chrome / Edge Manifest V3 扩展，在 B 站原生「稍后再看」页面增加发布时间和视频总时长排序。**不创建独立视频视图、不替换卡片、不自动滚动页面。**

适用页面：`https://www.bilibili.com/watchlater/list#/list`，以及 `/watchlater/#/list`、`/list/watchlater`。

## v0.5.1 — 修复点击排序无反应

以前的 v0.5.0 有两个确定缺陷：

1. **错误地要求所有视频都已渲染成 DOM 卡片**。稍后再看如果先渲染部分视频，扩展直接退出，用户点击后看不到任何变化。
2. **备用接口请求 ID 格式与接收方不一致**。备用请求会被页面脚本拒绝，导致排序数据无法读取。

v0.5.1 修复这两处问题，且不增加无关控件：

- 「排序」下拉框：默认顺序、发布时间新到旧／旧到新、总时长短到长／长到短。
- 获取完整元数据时优先复用 B 站页面请求结果；否则从后台接口读取，失败再使用网页上下文备用请求。
- 优先更新 B 站现有 Vue 响应式完整列表。**成功时无需刷新页面即可对全部数据排序**。
- 若 B 站未暴露完整响应式列表，立即根据完整排名排序**当前已经加载的原生卡片**，后续卡片出现时继续应用排名。无需滚屏、不创建扩展视图。
- 当接口不可用或原生卡片无法识别时，显示简短错误信息，避免静默失败。
- 保留原生卡片、布局、播放和删除操作，不改变 B 站服务器上的「稍后再看」顺序。

### 全量排序条件与限制

**全量排序只有在 B 站原生页面暴露完整列表的情况下才能直接保证。** 若 B 站只渲染部分项目且不提供可修改的完整响应式列表，CSS 只能调整**已经出现的卡片**；即使排名依据完整的 423 条数据，暂未加载的视频也不会凭空显示到第一页。悬停下拉框会显示当前排序范围说明。

这是「必须保留原生卡片、不复制或自绘、不滚动、不刷新」四项限制下的技术边界。当前没有在真实登录的 B 站账号中验证页面是否暴露可修改的完整 Vue 列表，因此不声称所有账号、所有 B 站版本都能真正无感全量排序。

## 安装或更新

1. 在 [GitHub 仓库](https://github.com/PyRookie1/bilibili-watchlater-sorter) 点击 **Code → Download ZIP**。
2. 解压到原扩展所在的文件夹，覆盖旧版源码；或在 `chrome://extensions` 中重新「加载已解压的扩展程序」。
3. **点击扩展管理页的刷新按钮**，然后刷新 B 站稍后再看页面。
4. 使用原生「最近添加」附近的「排序」下拉框。

如果点击后显示「排序失败」或「无法匹配原生视频卡片」，该提示表示扩展未成功应用排序，应先检查该页面的接口、类名或登录状态，不能将其算作成功。

## 开发及测试

要求 Node.js 20+，无第三方运行时依赖。

```bash
npm test
```

包含 API 完整性校验、接口和备用通道消息校验、423 项元数据排序、仅 15 张原生卡片情况下的排序、Vue 完整数据更新，以及无滚动/无重载约束。

关键文件：

- `src/content.js`：下拉框事件、元数据读取、原生卡片即时排序、错误提示
- `src/native-sort.js`：BV/AV 识别、全局排名映射和部分卡片排序
- `src/native-intercept.js`：原生网页接口、Vue 状态及页面消息
- `src/page-bridge.js`：同源备用请求
- `src/api.js`、`src/background.js`：完整列表接口读取和校验
- `test/`：回归测试

## 隐私

不读取用户 Cookie 值，不上传稍后再看清单。只保存本地排序偏好，直接复用 B 站的登录状态。

**测试范围声明：** GitHub 单元测试和模拟页面验证不能代替真实 B 站账号的浏览器端端到端验收。
