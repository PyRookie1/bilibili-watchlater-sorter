# B站稍后再看排序

基于 Chrome / Edge Manifest V3 的轻量扩展。直接使用 B 站自己的「稍后再看」页面和原生视频卡片，新增 **发布时间**、**总时长**的升降序选项。

支持 `https://www.bilibili.com/watchlater/list#/list`，以及对应的旧版和新版稍后再看路径。

## v0.5.0：修复首次排序时自动滚动

**不再自动滚动页面，也不为了排序而逐张触发懒加载。** 移除了额外刷新按钮、进度提示、独立排序网格。

现在优先从数据层实现原生排序：

1. 浏览器扩展在 `document_start`（B 站应用请求视频数据前）安装接口响应处理程序，支持原生 `fetch` / `XMLHttpRequest`。
2. 当 B 站请求 `/x/v2/history/toview` 或 `/x/v2/history/toview/web`，且响应为完整列表时，将响应中的 `list` 按当前排序偏好重排，**B 站仍自行创建、显示和管理原生视频卡片**。
3. 用户切换排序时，优先直接调整 B 站已存在的 Vue 响应式列表（如果当前版本页面公开了可识别的完整列表状态）；这样无需刷新。
4. 如果完整原生卡片本来就已渲染，使用 CSS `order` 即时排序，保留原生节点。
5. **兼容性回退：** 如果页面既没有可调整的完整响应式列表，也没有同时渲染全部卡片，将正常刷新页面一次，让第 1 步在 B 站下一次请求时生效。不会反复滚动。
6. 无论采用哪种方式，均不修改 B 站账号服务器中的稍后再看顺序。

只有 B 站真正返回**完整**视频数据时，才能保证全量排序。如果 B 站新版本改用未知接口、分页响应或不可访问的前端状态，扩展可能需要进一步适配，不能承诺在所有 B 站版本无刷新且全量排序。

## 功能

- B站默认顺序
- 发布时间：最新优先、最早优先
- 视频总时长：短到长、长到短（多 P 视频按全部分 P 总时长）
- 保留原生封面、排版、点击、删除及播放交互
- 只增加一个「排序」下拉框，不添加独立弹窗、额外卡片或批量操作功能
- 使用本地存储保存排序模式，不收集使用数据

## 安装与更新

1. 从 [仓库主页](https://github.com/PyRookie1/bilibili-watchlater-sorter) 点击 **Code → Download ZIP**，解压到本地。
2. 访问 `chrome://extensions`（Edge：`edge://extensions`），开启开发者模式，加载包含 `manifest.json` 的目录。
3. 若已安装旧版，用最新文件覆盖并点击「刷新扩展」，然后刷新 B 站页面。
4. 在 [稍后再看](https://www.bilibili.com/watchlater/list#/list) 页面顶部原生排序菜单旁，使用新增的「排序」下拉框。

## 测试

需 Node.js 20+：

```bash
npm test
```

测试包括：完整列表排序、接口缺失/截断检查、原生 Fetch 数据拦截、Vue 列表原地更新、非稍后再看接口不拦截、原生 DOM 不被替换，以及源代码中不存在自动滚动行为。

**真实 B 站账号的浏览器端测试尚未完成**。自动测试验证的是扩展逻辑，不能替代对 B 站线上页面版本的验收。

## 工程文件

- `src/sort.js`：排序算法
- `src/native-intercept.js`：原生 API 数据优先排序、页面状态同步
- `src/native-sort.js`：已完整渲染时的原生卡片排序兼容层
- `src/content.js`：唯一的嵌入式排序下拉框
- `src/api.js`、`src/background.js`、`src/page-bridge.js`：完整列表读取及备用路径
- `test/`：Node 自动化测试

## 隐私

使用当前 B 站登录状态；不会读取或上传 Cookie 值。排序偏好仅保存在本机，不上传观看列表，不使用额外服务器。
